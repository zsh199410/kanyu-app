# 三术合参 Web：生产前端恢复与 V6 呈现层

来源：https://bazi.vip668.xin/，2026-11-11。这里恢复的是站点实际提供的静态前端，不包含后端源码、数据库、服务端排盘引擎或部署凭据。

`app.js`、`auth.js`、`chartdepth.js`、`qrcode.min.js`、`style.css`、图标保持获取时的字节内容。`upstream-sha256.json` 保存来源摘要；`index.html` 仅增加 v6.css / v6.js 两个资源引用。V6 层复用原来的 data-theme、哈希路由和 DOM 字段，不新增账号/主题存储、不改 API、排盘规则或请求口径。

V6：31个完整工具入口收纳进可搜索 dialog；手机底栏为5个核心入口＋工具；人物表单按屏宽折叠；核心排盘2×2；浅深主题、正文无衬线/标题衬线、20/15/16px间距、18px圆角、44px命中区；减少动态效果与打印降级。

## 已验证范围

浏览器把本目录的静态资源替换到真实站点同源地址，继续读取原来的后端；没有上线部署，没有提交建档或修改账号资料。七个屏宽320/375/390/430/768/1024/1440：无文档横向溢出；手机底栏64px；31个目录入口完整；工具搜索、跳转、Escape关闭、焦点返回和主题切换通过。截图/结果在 docs/design-v6/evidence。

这不代表服务端算法、所有有档案的业务流程或真机传感器已通过验证。

## 部署边界与回滚

部署到原站点的静态资源目录，保持原后端路由和会话同源。先备份原 index.html；新增 v6.css/v6.js，并更新 index.html 的两个引用。其他恢复文件只用于版本核对；若服务器已有更新版本，不应覆盖其 app.js/auth.js 等业务代码。

回滚只需恢复原 index.html（或移除两个V6引用），不迁移、不删除用户数据。不能把本目录单独托管成另一个域名后宣称原API、登录会话和全部功能仍然可用。

实际服务器/部署仓库尚未确认，因此当前站点的公网版本未被本次代码更新。
