# DesignSystem V6：核心页面与交互定稿

基线：`main 1ae6503`。本文件是依据现有 SwiftUI 源码制定的实施规格；尚未完成原生截图驱动的视觉验收，不代表性能或全部算法已经验证。仅改变呈现、导航容器及交互反馈，不更改排盘规则、引擎输出、已有 Tests 或金标准 JSON。

## 1. 全局页面契约

- 信息顺序：**人物与时间上下文 → 核心盘面 → 可理解的结论 → 盘面依据/原文 → 保存、回验与导出**。不可把生辰、时区、真太阳时和流派口径藏进装饰。
- 保留 `HomeTabs.swift/RootTabView` 五个 Tab：合参、八字、紫微、奇门、堪舆；手相面相作为首页旗舰入口，不追加拥挤的第六个 Tab。
- 页面左右 20pt、章节间 15pt、卡内 16pt、卡圆角 18pt continuous；标题与相邻正文间 8pt，同行控件间 8–12pt。内容底部安全余量 32pt，叠加浮动工具栏时使用 `safeAreaInset` 实际占位，不以任意超大 padding 猜测遮挡。
- 导航标题以系统衬线语义字号 `.title`（标准 28pt）为基准；封面展示标题可用 `.largeTitle`（标准 34pt）；章节标题 `.title3` semibold serif；正文 `.body`，辅助 `.subheadline`；正文行距 4pt、解释段行距 5pt。默认正文 17pt、辅助 15pt，缩放随 Dynamic Type；仪器刻度可 11–12pt，但必须另有可放大的等价数值区。不得以全局字号上限掩盖溢出。
- 所有角度、年份、百分比使用等宽数字。年份使用 `String(year)`/显式不分组格式器，不用可能按本地分组的裸数字文本插值。已经格式化为字符串的真实干支、时间与度数不再二次本地化改写。
- 玻璃只出现于悬浮导航、底部控制胶囊、抽屉控制层；命盘与长文字用不透明内容底。iOS 26 使用有 availability guard 的原生 `.glassEffect`；iOS 17–25 回退系统 Material；Reduce Transparency 回退实色。印刷/PDF 不采用实时玻璃。
- 主题要区分按钮填充、按钮前景、链接和装饰金：雅金 #9E782F 对象牙 #FCFBF7 静态对比约 3.91:1，不用于小正文；香槟金 #D1AC53 填充按钮使用黑曜石 #111317 前景（约 8.62:1），不可配白字（约 2.16:1）。这些数值是静态 sRGB 计算，不代表整页已通过可访问性验收。
- 可交互命中区最少 44×44pt。不可把每颗小星、神煞或单个 10pt 标签直接当作唯一命中区；采用宫位/柱的整体按钮再进入细项。
- 装饰线、飞线、纹样必须 `.allowsHitTesting(false)`，VoiceOver 隐藏装饰；颜色不能作为选中、吉凶、时间层或五行的唯一标记。
- 有效状态至少区分：未建档、未选择、加载、可读结果、空结果、输入错误、服务不可用、保存失败。不能在错误或缺数据时补一个看似正常的个人盘或百分比。

## 2. 首页：六层智能工作台

**现有文件/组件**：`KanyuApp.swift/HomePageView` 的 `brandHeader`、`personSwitcherCard`、`todaySection`、`todayAlmanacCard`、`todayFortuneCard`、`primaryBentoGrid`、`recentToolsSection`、`allToolsLink`；`DesignSystemV6_Extensions.swift/KyProfileHeader`、`KyPersonSwitcher`；`AllToolsView.swift/ContextualToolDestination`。

### 最终结构

1. **品牌导航**：导航栏左为 24pt 浑天仪线标，中为“三术合参” serif headline，右为 44pt 命主印章按钮进入个人中心。主内容中不再重复整块品牌卡、页眉营销词和头像入口；旧 `brandHeader` 的个人中心可达性必须迁移后保留。
2. **当前命主卡**：姓名 20pt serif；身份与出生资料一行可折行 15pt；四柱用四枚等宽数字/干支胶囊排列；头像 48pt，外围 1pt 五行色环。日主文字与五行图标同时展示，外缘光晕最大不透明度 8%，无永久呼吸。显示当前大运已存在的名称/阶段摘要；没有阶段数据则写“暂无阶段资料”，不在视图层推算。
3. **今日天地**：公历主日期 28pt 等宽、农历/干支/节气 15pt；宜忌分成两个带文字标签的区块。整个卡进入万年历，择吉单独 44pt 辅助按钮，禁止两个重叠点击区。交节信息来源于现有历法字段。
4. **五主题阅读入口**：综合、事业、财富、关系、身心五个等权按钮，横向可滚或大字号时改两列。此处**不画虚构的五维气运分数或进度**。现有 `AlmanacModule.swift/TodayFortuneCard` 只有三条文字（五行旺衰、冲合、岁运），没有五个可追溯数值。可显示现有对应解读的一句摘要；未映射主题写“查看主题解读”，无命主写“建档后查看”，不足资料写“资料不足”。如果未来引擎提供正式指标，另立需求验证后接入。
5. **四大旗舰矩阵**：八字、紫微、奇门、手相面相，维持当前目标页及手势。两列、列距 12pt、行距 12pt；卡内 16pt，图标 28pt，标题 20pt serif；描述 15pt、最多两行后提供完整可访问标签。卡高度由文字决定，不锁死固定高度。辅助字号进入无障碍档时切一列。堪舆仍可从底部 Tab 直达。
6. **继续与收纳**：最近使用保持最多六项，人物与工具分类型显示；“全部工具”是完整目录，不从注册表删除工具。白话指南作为这一层的清晰常驻入口；到期回验与证书提醒仅在有真实事项时显示，不抢占常态首屏。

### 保留与验收

- 必须保留建档、切人、个人中心、五 Tab、指南、全部工具和所有最近使用路由；所有个人盘入口经 `ContextualToolDestination`，不恢复 `Date()` 伪造生辰。
- 切换人物后标题、命盘、解读、导出对象同步；任何缓存必须继续使用当前既有的上下文键。设计层不更改人物 UUID、存储结构和排盘口径。
- 空档案：显示简洁的建档卡与单个主操作；日历、知识、罗盘仍可独立进入。建档取消不能改变人物数据。
- 单手操作：从首页打开任一旗舰功能至多一次点击；切人/建档入口始终 44pt 可触达；页面所有悬浮按钮有安全区占位。

## 3. 个人中心与档案管理

**现有文件/组件**：`HomeTabs.swift/MyView`、`personalProfileSection`、`myLink`；`PeopleModule.swift/PeopleView`、`PersonDetailView`、`PersonFormView`；`PersonQuickBar.swift`；`ReportCenterView.swift`。

- 顶部档案名片沿用同一命主印章和出生资料格式；不再添加第二套身份评分。首组“人物档案 / 报告中心 / 备份恢复”，次组“前瞻与回验 / 测量记录”，末组“显示与字号 / 语言 / 排盘口径 / 关于”。高风险恢复与普通外观设置分区，不在换主题时触发恢复或重新排盘。
- `MyView` 现有 `@AppStorage("uiStyle")` 的 `system/light/dark` 三值保留，名称改成“跟随系统 / 宋纸青黛 / 暗夜玄金”；不新增同义主题存储键。两主题小预览只用固定样例，不用真人命理数据。
- 现有“到期核验命中率”等文案改成“回验记录与结果”，不把个人勾选当统计准确率；只调整呈现文案，不改回验模型或评分算法。
- `PersonQuickBar` 选中项用填充、描边和“当前”文字三重提示；标签字体至少 `.subheadline`，保留完整名字的 VoiceOver 标签；不在大字号状态强行压成一行。
- 档案表单清楚区分出生资料和展示设置；“取消”维持当前语义，保存失败时错误可见，不能用按钮动画假装写入成功。

## 4. 八字细盘：不透明的精密册页

**现有文件/组件**：`BaziModule.swift/BaziResultView`、`plateCard`、`plateGrid`、`pillarDetailView`、`enlargedPlateView`、`timeCard`；`DesignSystemV2.swift/WuxingBarsView`、`EvidenceChainView`；`DesignSystemV6_Extensions.swift/KyBottomSheet`；`InterpretModule.swift/InterpretView`。

- 首层固定显示：命主、钟表时间/真太阳时说明、当前时间层、四柱。专业模式继续保留，默认状态不在视觉重构中擅自更改；简单模式使用明确文字而非隐去资料后仍称“完整盘”。
- 四柱外部连续圆角 18pt，内部用垂直 0.7pt 分隔。天干 30pt serif、地支 28pt serif；列名与十神 `.subheadline`，藏干和神煞可折叠。五行色配“木火土金水”或属性小标；未选中无微光。
- 点柱选中：1pt 青黛/流金描边与不透明度 6% 底色，140–180ms 淡入；牵动柱同时出现“合/冲/刑”等来自既有 `currentRelations` 的文本。装饰不改变关系计算，不通过颜色增补关系。
- 点干支/十神/神煞：复用现有 `.sheet` 和 `KyBottomSheet`，初始 `.medium`、可拉 `.large`。抽屉顺序为词条、白话、一条本盘事实、已有原文与出处、相关干支。缺少可信原文显示“暂无对应原文”，不自动写成古籍句子。
- 保留长按/放大四柱、等价文字阅读、已有 VoiceOver 名称、时辰对照、牵动柱反向定位，以及 `verificationOwnerID` 传递。不要把专业盘信息只剩海报式摘要。
- 大运/流年/流月/流日四层胶囊 44pt 最小触达；选中项有文字与位置标记。保留 `SceneStorage` 键和 `YunSource` 互斥规则；边界索引需在呈现层校验，尤其 `safeDayun` 目前只钳制上界、`selectedPillarStored` 只检查非负。可以做 UI 状态钳制，不改变排盘数组内容。
- 原有 `pulse`/`KyMotion.breathing` 无限动画改为单次选中反馈或静止高亮；Reduce Motion 完全取消缩放/位移，保留立即显现的选中边框。

## 5. 紫微十二宫：单层飞线与明确的时间层

**现有文件/组件**：`ZiweiModule.swift/ZiweiBoardView`、`gridBoard`、`textBoard`、`flyLinesOverlay`、`palaceCenter`、`replayFlyLines`、宫位抽屉；`ZiweiReadingView`、`ZiweiYearView`。

- 方盘坐标、宫位顺序、星曜、亮度和四化一律读取既有 `ZiweiChart`。保留当前 `cellPos` 对应关系，不能为了视觉对称调换命财官迁宫位。
- 本宫用 1.2pt 金边、6% 金底与“当前宫”标记；其余三方四正用虚线边/连线和可读宫名说明。选中微浮 2pt、持续不超过 180ms；避免改变网格布局或遮挡邻宫文字。
- 单一 Canvas 画线：三合雅金、对宫朱砂，非选中线不超过 22% 不透明度；450ms 内单次依次显现，停止后静止。不得叠加多层模糊光斑。Canvas 只画装饰，宫位按钮与 VoiceOver 顺序独立。
- 四化徽记用“禄/权/科/忌”明确文字；可用翠玉、青黛、雅金、朱砂配色，但不把“忌”画成错误/故障提示，也不隐去其他四化。徽记最小可读文本 12pt，完整释义进入宫位抽屉。
- 保留已经存在的 `.dynamicTypeSize.isAccessibilitySize → textBoard`；不要强迫最大字号仍使用四列方盘。保留 1.0–1.8 的放大、双指缩放与回命宫入口；放大不得裁切必读宫位，提供重置与等价列表。
- `palaceCenter` 当前行高 114pt、gap 5pt 写死；若改字体与宫格尺寸，应把同一套实测 geometry 同时交给格子和 Canvas，不能只放大文字后继续画旧位置。
- 顶部清楚标注本命/大限/流年、年份及当前人物；切人或切时间层要同步抽屉标题和事实，不能只更新外围装饰。`selectedStored` 的范围在 UI 端限制为 0..<12。

## 6. 奇门九宫：控制台与盘面分层

**现有文件/组件**：`QimenModule.swift/QimenHomeView`、`cachedChart`、`recompute`、图层开关、九宫放大与宫位详情。

- 头部一张“起局收据”：公历时刻、真太阳时状态、定局法、阴阳遁局数、寄宫/暗干设置，来自既有图表字段。收据占 1–2 行摘要，点开完整；不把口径藏进仅图标按钮。
- 常用时间与方法用一行控制条；其余参数收进“起局设置”抽屉。原有开关及 `recompute` 调用保持，视觉重构不改重算触发、默认选项或缓存。
- 九宫卡内容层级固定：宫位/方位 → 门与主星 → 天地盘干 → 神与格局标签。选中状态有描边和文字，不用满屏彩色底；中宫寄宫规则只显示引擎输出，绝不在 UI 自行补推。
- 天盘/地盘/星/门/神五个图层开关继续保留 `SceneStorage` 键；关闭任一层只隐藏显示，不改变局或解释。大字号使用宫位列表，保留九宫总览切换。
- 点击宫位用同款底部抽屉显示“该宫是什么 → 本局字段 → 既有解释与依据”；无图表或计算失败显示具体状态和重试入口，不能渲染假九宫。
- 正在重起局的现有提示用静态行内状态或微小进度指示，不盖住全部盘面、不反复弹窗；Reduce Motion 不播放九宫进场位移动画。

## 7. 堪舆压盘与专业罗盘：恒深色仪器

**现有文件/组件**：`CompassModule.swift/CompassStandaloneView`、`CompassLock`、`CompassBearingResolver`、`CompassSampleReceipt`；`FloorPlanOverlayView.swift/FloorPlanOverlayView`；`KanyuApp.swift` 勘察工作台、拍摄、AR/RoomPlan 的视图段。

- 恒深色背景 #111317，卡/控制面 #1A1D23，主读数用高对比暖白等宽数字 36–44pt，单位 17pt；磁北/真北、坐/向分别有明确文字，不靠针颜色判断。
- 度数和二十四山位于读数主区域，精度、倾斜、校正来源与位置在紧邻的质量区；未知、无效、来源变化、低精度等真实状态不能被装饰盖住。
- 本轮只改皮肤与控件。`CompassBearingResolver`、`CompassSampleReceipt`、输入有效性、采样中止、保存门禁的条件和值均保持；失败时继续展示真实原因，不能用光效让“不可用”看成“已校正”。
- 罗盘机械触感只在真实操作跨过一个 15° 山界、锁定成功或重置时触发；不是每个传感器帧触发。一个手势复用生成器，手势开始 prepare，同类 selection feedback 至少间隔 125ms；应用内关闭触感时停止。
- 户型工作区主画布上层只保留导入、方向/模式、重置三类工具，参数集中到底部控制面板。保留当前 `overlayMode`、`overlayOpacity`、`centerOffset`、`lastOffset`、`selectedPalace` 和导入图流程。
- 中宫拖动只改变 transform；拖动中不生成新户型图、重编码图片或重新排盘。十字准星有 44pt 命中区与可访问的“上/下/左/右微调、居中”替代操作。
- 飞星遮罩默认沿用当前 0.55 不透明度；滑杆以百分比显示，变化仅作用 opacity；不要为了示范重新设置算法所用运数或朝向。样板户型中的面积/房名必须明确标为示意，不能被误认成用户测量结果。
- 权限拒绝、无定位、无真北、导图失败、设备不支持 AR/LiDAR 各有明确状态；仪器恒深色不强迫系统其他页面也改成深色。

## 8. Web 端呈现契约

此仓库当前未找到可运行的 Web 产品工程；新增 `design/web` 是可移植 CSS/主题适配器参考，尚未接入产品。不得把不存在的 `app/static/...` 当成已核实路径，也不把设计预览冒充 Web 正式端改造。连接实际 Web 仓库后，按其构建系统接入相同语义 token。

- 检查 320/375/390/430/768/1024/1440px；窄于 360px 时核心入口单列，普通手机两列；768px 起工作台两栏，1200px 起 260px 导航＋主区＋320px 解释栏，栏距 24px；手机边距 20px、章节 15px，与 App 保持逻辑节奏。
- 桌面首页左侧当前人物及阶段上下文，右侧历法与主题摘要；旗舰入口四列或 2×2，工具目录可检索；不照搬手机页面无限拉宽。
- CSS `prefers-color-scheme` 与现有主题偏好联动；`prefers-reduced-motion` 移除位移/循环效果；透明度关闭或不支持 backdrop-filter 时回退不透明底色。
- 每个宫位/干支是可键盘聚焦的语义 button，Enter/Space 打开详情，Escape 关闭，焦点回到触发按钮；抽屉具备 dialog 标题与焦点管理。Canvas/SVG 装饰不代替文字盘。
- Web 只消费既有 API 的计算结果；缺数据、未知分数、接口失败或旧规则版本均如实标记，禁止自行在 CSS/前端生成“综合评分”。

| P0 基线 | 现有五 Tab、工具注册表、所有目标页、主题设置、海报入口 | 保存当前主分支 SHA 与正常/缺档状态证据；原生浅/深/大字号截图，记录未覆盖项；不改 Tests/金标准，不把构建通过当视觉通过 |
