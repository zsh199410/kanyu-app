# 手机复测精确步骤 · 切换窗口用（Issue #73，D7 就绪版）

> 前置条件（缺一不可，缺了就停，不要先测）：
> 1. GPT 已批 D7（#73 有明确批准评论）；2. 机主授权切换；3. 冻结版源 SHA 已记录（见 §1）。
> 正式组「免费节点池」、生产订阅、生产定时器在复测完成前一律不动。
> 本文件是 D4 direct-test 计划（`docs/direct-test-onepager.md`）的切换窗口执行版；
> staging 的冻结文件是合成固件（TEST-NET，见 `staging/frozen-clean14-manifest.json`），
> 真实切换时按同样程序冻结真实 14 行并以真实 SHA 为准。

## §1 冻结（助手做，手机不动）

1. 记当前生产订阅：行数 + SHA256 全值 + 发布时间（`pool-new.txt`）。
2. 停旧写手：`systemctl stop pool-publish.timer pool-sync.timer pool-crawl.timer pool-test.timer pool-test-full.timer`（先停定时器，不停服务本身；服务无常驻写手）。
3. 冻结源版本：把当前生产文件复制为冻结版，记 SHA（此 SHA 即本次复测唯一目标版本）。
   冻结后任何新抓取/新测试结果都不得改动冻结版；下一轮 :07 到来时跳过发布（定时器已停）。
4. 门禁版发布准备：gate publish 对冻结版跑门禁（须 0 失败）；门禁拒绝则停在此步，查原生证据新鲜度，不要强行发布。
5. 记锚点：served 文件 SHA + 行数、bridge 文件 SHA + 行数（复测前后核对用）。

## §2 手机原生整组复测（机主做，唯一验收）

1. 手机只用移动数据（关 Wi-Fi），确认 Surge 在运行。
2. 刷新「免费节点池」订阅，确认成员数与冻结版行数一致（不一致先停，找助手核对）。
3. 对该组点一次完整测速，等**全部**成员出结果（不要中途截图）。
4. 截图：全部成员 + 结果，带状态栏时间；分段截必须无遗漏、无重叠断层。
5. 通过标准：**全部成功且全部 <300ms**。任一失败或 ≥300ms 即不通过，停在 §4 回滚。

## §3 DIRECT 三场景（机主做，紧接 §2，正式组不动）

新建临时测试组 `DIRECT-TEST`（`smart`，与正式组同 url-test 参数 `interval=600, tolerance=100, timeout=0.3`），加一条只影响测试域名的测试规则；助手提前备好三份测试订阅并核对行数与 SHA（全失败 3 条已死节点 / 空组 0 行 / 单节点 1 条新鲜原生通过 <300ms、24 小时内、当前 served 版本 SHA 下）。

- **情形 A 全失败组**：policy-path 换全失败订阅，刷新，成员数 3；测速一次，3 条应全失败；打开测试域名，记能不能打开、出口 IP 与运营商 IP 是否相同、Requests 里的 policy。**通过：打不开，且无 DIRECT 记录。** 能打开且出口是运营商 IP 即落 DIRECT，记不通过，立即停测并报告。
- **情形 B 空组**：policy-path 换空组订阅，刷新；记 Surge 表现（0 成员保留 / 拒绝加载报错 / 组消失）；再打开测试域名记同 A 三项。**通过：打不开，且无 DIRECT 记录。** (b) 本身就是 fail-closed 证据。
- **情形 C 单节点组**：policy-path 换单节点订阅，刷新，成员数 1，测速确认 <300ms；打开测试域名：应能打开，出口 IP 与运营商 IP**不同**，Requests 里应为 `DIRECT-TEST`。**通过：单节点正常时走节点；节点失效时请求失败，不落 DIRECT。**

收尾：删除 `DIRECT-TEST` 组与测试规则；删除三份测试订阅（助手侧删托管文件）；核对正式组「免费节点池」成员数与测试前一致，正常上网一次确认无影响；三情形截图 + 记录发助手整理成证据表回 #73。

**判定：三种情形全部不落 DIRECT 才算证明完成；任一落 DIRECT 即正式切换阻断项。**

## §4 回滚（任一步不通过即执行）

1. 恢复上一版订阅（回滚 SHA = §1 记的切换前生产 SHA），手机刷新确认成员数回到切换前。
2. 恢复旧定时器（`systemctl start` §1 停掉的各 timer），观察下一个 :07/:15 周期日志。
3. 助手重取 served/bridge SHA 与行数，与 §1 锚点逐项核对，必须完全一致；不一致先停下来查原因。
4. 不通过原因 + 回滚 SHA 发回 #73，等下一轮裁决，不要反复重测同一版本。

## §5 切换完成确认（§2 + §3 全过才做）

1. 门禁版正式发布冻结版；手机刷新，成员数 = 冻结版行数。
2. 原生整组再测一次（同 §2 标准），确认 0 失败、0 个 ≥300ms。
3. 启用门禁定时器（:07 publish、:15 sync），旧写手定时器保持停用；观察连续两个 :07/:15 周期 health.json 均为 healthy。
4. 证据（冻结 SHA、两轮原生截图、DIRECT 三情形记录、health.json）整理回 #73。
