## 2. 实现了什么

**双门禁（`pool/native_gate.py`，新模块）**——发布 allowlist 唯一标准 =
最新同一版本手机原生成功且 <300ms、无后续原生失败；P0 只作健康信号：
- 每条指纹取其在被发布版本上的最新一次原生结果；无同版本证据 → 拒绝。
- 同版本最新结果须成功且 <300ms；P0 <280 但原生失败/超线 → 拒绝。
- 同版本通过之后、任何更新一轮原生测试里该指纹失败/超线 → 通过作废。
- 时间戳 0 < ts <= now（未来时间戳一律拒绝），24h TTL。
- 原生通过但 P0 最新在 (280, 297] → 有条件候选（放行 + 标记）。

**共享锁（`pool/publish_lock.py`，D0 原样复用 + D1 扩展）**：
- publish / sync / rollback 共用同一把 flock（`lock/publish.lock`），
  门禁判定 + 写文件在同一把锁内完成（无 TOCTOU）。
- D1 扩展：锁内原子写 `_atomic_write_inner`；快照与当前文件各带
  `.meta.json` sidecar（记 `source_version_sha`），回滚锚点据此复核。

**三条路径（`pool/publish.py` / `pool/sync.py` / `pool/rollback.py`）**：
- publish：候选行（含钉选，无豁免）过原生 allowlist；0 条通过则拒绝，
  旧订阅保留。
- sync：源文件逐行重过门禁，须全部通过且非零；否则已服务文件不动。
- rollback：锚点按其自身版本过门禁，须全部通过且非零；无版本 sidecar
  的锚点一律拒绝。

**固件（`fixtures/`，全合成）**：TEST-NET 主机 + 密码
`TEST-ONLY-NOT-A-REAL-NODE`，只镜像 13:24 的判定结构（14 通过 / 4 条
P0 <280 但原生 320–1018 / 26 失败）。固件池 SHA `f6083ad90eac…`，
干净 14 行 SHA `6074082847c3…`。

## 4. 实现中发现并修正的一个口径问题

第一版双门禁按“最新一次原生结果（不限版本）须为同版本通过”实现，
导致：只要存在更新一轮他版本原生测试，发布旧版本会 0 条通过——
回滚到旧版本快照在任何复测后都几乎不可能，违背回滚作为恢复路径的
本意。已修正为 GPT 原文的准确读法：**同版本最新结果 + 无后续原生
失败**（后续他版本通过不作废，只后续失败作废）。修正后 24 项测试
全过，含 supersede 用例（T01 在更新一轮里失败 → 作废；其余 13 条
更新一轮仍通过 → 保留）。
